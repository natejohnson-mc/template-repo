# Decision records

Create a numbered Markdown record when future work will need the reasons for a
significant project choice. Routine fixes do not require a decision record.
Track progress in [project status](../status.md).

## Record structure

Name records with a sequence and descriptive title, such as
`0001-descriptive-choice.md`. Include:

- A title and status: proposed, accepted, or superseded.
- The problem, constraints, and links to supporting evidence.
- The chosen approach, alternatives considered, and tradeoffs.
- Conditions that would require reconsideration.
- A link to a replacement record if the decision is superseded.

Preserve the reasons for a superseded decision. Keep implementation progress
and execution results in the owning component record.
