# Repository starter

This template provides predefined documentation destinations for people and AI
agents. It includes no application code, selected language, development
environment, CI configuration, or deployment tooling.

Use [repository instructions](AGENTS.md#task-routing-and-ownership) to find the
authoritative section for a task. The starter keeps related guidance in sections
of five core files rather than separate placeholder documents.

For personal instructions that apply across repositories, copy the
[user root AGENTS.md preferences](docs/user-root-agents.md) into your user-level
root `AGENTS.md`. That document is a reusable example for users, not repository
instructions.

The repository's [Codex configuration](.codex/config.toml) is maintained as
described in [Development: configuration](docs/development.md#configuration).

## Use this template

1. Create a repository from this template. Replace this README with the
   project's name, purpose, scope, entry points, and actual source layout.
2. Populate [development](docs/development.md) with project setup, runnable
   commands, checks, configuration ownership, and delivery requirements.
3. Use [project status](docs/status.md) for ongoing work, pending verification,
   and opportunities when they exist.
4. Adapt the [pull request template](.github/pull_request_template.md) to the
   project's review process. Add recurring repository rules and skill triggers
   to `AGENTS.md` as they become established.

Replace starter text as the project takes shape. Do not treat unconfigured
sections as implemented tools or verified procedures. Consolidate or remove
unused sections and keep routing and links current. Follow the
[documentation policy](AGENTS.md#documentation-workflow) when deciding whether
content needs a separate document, such as a configuration contract, component
record, or runbook. Add a documentation index only when the growing collection
needs navigation beyond the existing routing table.
