# Repository starter

This template provides a linked documentation structure for repository work by
people and AI agents. It includes no application code, selected language,
development environment, CI configuration, or deployment tooling.

Start with [repository instructions](AGENTS.md). Use the
[documentation map](docs/overview.md) to find the record for a task and
[project status](docs/status.md) to find pending work.

## Use this template

1. Create a repository from this template. Replace this README with the
   project's name, purpose, scope, and entry points.
2. Record the actual prerequisites, setup commands, and checks in
   [development](docs/development.md). Populate
   [Run repository tools](RUN_TOOLS.md) when runnable tools exist.
3. Define the project's configuration and runtime boundaries in the
   [configuration contract](docs/configuration-contract.md).
4. Add source locations and task-specific records to the
   [documentation map](docs/overview.md). Populate
   [project status](docs/status.md) with the first scoped work and next action.
5. Adapt the [change workflow](docs/change-workflow.md) and
   [pull request template](.github/pull_request_template.md) to the project's
   review and delivery process.
6. Add repository-specific rules and skill triggers to `AGENTS.md` as they
   become established. Keep cross-repository instructions in the user's root
   `AGENTS.md`.

Adapt the starter to the project's size and needs: consolidate or remove unused
records and update the ownership map, instructions, and links together. Replace
starter text as the project takes shape. Do not treat unconfigured sections as
implemented tools or verified procedures. Use the
[documentation rules](AGENTS.md#documentation-workflow) to decide what merits a
maintained record and how readers will find it.
